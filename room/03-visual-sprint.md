# Visual sprint — next phase

The editorial architecture is now parked. The next work is visual only.

## Aim

Move far away from the current dashboard / Second Brain product feeling while preserving the underlying content and routes. Test a simple personal internet interface with the directness of George Hotz and Lex Fridman, but capable of carrying essays, project imagery, diagrams, and visual explanations.

## First visual questions to answer in code

1. Can the left vertical sidebar become a calm horizontal or editorial navigation without making the site harder to use?
2. Can the home introduce Yago, face, identity, and work with very little interface chrome?
3. Can the visual system support both clean photographs and rough explanatory diagrams?
4. Can red/blue/graphite become a functional authored palette rather than a neon tech theme?
5. Can the Second Brain retreat into a quieter, more useful archive surface?

## First implementation principle

Change one visual surface at a time. Start with the global shell and home composition. Do not redesign every view or rename content until the visual direction earns it.

## Pruning principle

This is a redesign and a simplification pass, not only a reskin. Audit old visual metaphors, legacy controls, duplicated UI, public editing affordances, and dependencies that no longer support the intended experience. Remove them when they have no clear user value. Keep the underlying knowledge and publishing power, but make the public surface much lighter.

The old 3D graph, flashy Second Brain treatment, node-editing controls, and dashboard-like presentation are candidates for removal or containment. Do not preserve a feature merely because it already exists.
